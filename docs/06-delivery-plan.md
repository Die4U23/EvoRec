# 交付计划与需求追踪

任务按依赖推进，不在算力和数据尚未验证时给出固定完成日期。工期在 R01 后根据实际资源估算。

## 1. 任务拆分

| ID | 工作 | 依赖 | 完成证据 |
| --- | --- | --- | --- |
| F00 | 框架文档、最小服务、契约导出 | 现有 PRD 和选型 | 当前检查记录 |
| R01 | 设备与数据可行性、小样本基线 | F00 | 数据来源、样本统计、资源与结果记录 |

| R04 | 生成式及最邻近方法复现 | R03 | 官方复现差异、时间及候选协议 |
| R05 | 动态商品与可达性诊断 | R04 | 分组结果与失败样例 |
| R06 | 预算路由与消融 | R05 | 多种子质量及总成本比较 |
| M11 | 数据库迁移与示例会话 | F00 | 实库约束、隔离和重置验证 |
| M12 | 基础推荐接口与请求留存 | M11、R03 | 真实数据链路与输入快照 |

## 3. 完成的定义

任务完成需满足：实现与需求对应；必要的正确性检查通过；结果或限制有记录；运行说明与实际一致。数据库、模型、前端和性能结果必须分别验收，不能用接口存活代替整体验收。

每个版本记录已完成、未完成、已知限制和下一阶段依赖。没有真实实验时，看板保留空状态；模板文件在运行前保持 template 标记。
