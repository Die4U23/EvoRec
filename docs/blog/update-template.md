# EvoRec 项目实录更新模板

主文：[从零构建 EvoRec](evorec-project-log.md)。本文件是写作模板，不是已完成的更新记录。

## 每次更新的步骤

1. 读取本次代码改动、任务状态和真实验证结果，确定已经完成的内容。
2. 修改主文顶部的最近更新日期、当前阶段和进度表。
3. 在对应主题章节补充原理、例子、实现与结果，保留仍未确认的问题。
4. 在主文更新日志顶部追加本次记录。
5. 核对图表、数字、代码和链接；结论改变时注明旧认识与修正原因。

## 复制以下结构填写

### YYYY-MM-DD｜本次推进的主题

**本次问题：** 说明为什么需要推进这项工作，以及它对应哪个研究问题或产品需求。

**实际改动：** 说明修改了哪些设计、代码或实验配置。关联实际任务 ID、代码版本或文件，不编造尚不存在的提交。

**验证过程：** 写明环境、输入、数据范围和检查方法；如果没有执行验证，明确记录原因。

**结果与证据：** 放入真实数据、图表、截图、日志或报告位置。比较实验需给出基线、评价口径与计算条件。

**遇到的问题：** 记录失败现象、排查动作及仍未证实的解释。

**当前结论：** 说明证据能够支持什么、适用于什么条件，以及不能据此推出什么。

**下一步：** 写一个具体任务，并说明怎样判断它完成。

## 实验记录的附加字段

| 字段 | 需要记录的内容 |
| --- | --- |
| 数据 | 来源、快照、时间切分、样本数与候选范围 |
| 配置 | 模型、参数、随机种子与调参协议 |
| 环境 | 设备、依赖、并发与资源限制 |
| 指标 | 定义、整体与分组结果、波动或不确定性 |
| 成本 | 训练或推理耗时、内存、计时边界 |
| 追溯 | 代码、数据、模型、索引和结果标识 |

发布到博客站点时，应将项目内相对链接改为实际可访问的项目或文档链接。正文中的流程图使用 Mermaid，需要目标页面支持渲染或在发布时转换为图片。
