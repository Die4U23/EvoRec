# R06 多兴趣召回与排序适配协议

登记日期：2026-09-17。配置：[r06-multi-interest.json](../../research/configs/r06-multi-interest.json)。本文件在抽取 R06 数据、查看验证结果和最终测试之前提交。预期收益是假设，负结果也完整交付。

## 研究问题与固定预算

R05 冷目标候选并集覆盖率仅 127 / 7,088。R06 检验把历史压成单一均值是否损失兴趣方向，并检验排序器是否需要适应新的候选分布。方法是可解释的近期多向量检索，不声称复现 MIND 或 ComiRec。

内容编码器完全复用 R05 在 2017 年前训练的 TF-IDF/SVD。原始文本字段、128 维表示、历史限制 50 和均值衰减 0.8 均固定。多兴趣只取最后 8 次正反馈事件；从最新事件起距离 j 的分数为 0.9^j × max(cosine, 0)，对这 8 个方向取最大值。缺失表示不生成方向，距离仍按原事件位置计算。零分按商品 ID 排序。

均值 Top200 与多兴趣 Top200 以等权 RRF（常数 60）合并为内容 Top200；协同 Top200 不变，并集最多 400，最终输出最多 200。各来源先执行严格时间可用和全部已见过滤，不能注入目标。无可表示历史时统一使用原热门回退。记录逐请求来源列表、最终内容列表及并集；标明候选数量不等于计算预算。

## 数据与访问顺序

从已有、已校验的完整 Video Games 源文件选择用户哈希桶 4 / 20，排除 R01 用户；完整扫描至 EOF。验证与 R01–R05 的用户交集均为零。训练用户仍为 R03；训练结束、验证结束时间沿用配置中的 1628643414042 / 1658002729837 毫秒。

先生成样本与指纹，训练只读取两个原滚动窗口（2017–2019、2020–2021）。先完成所有训练、验证选轮、检查点重载与方法选择并落盘，再显式开放新桶的 test。样本构造可扫描完整时间范围以形成固定数据文件，但不得提前生成测试候选、查看测试质量或据测试调参。商品与日历和旧轮重合，因此不是跨时间或跨领域独立泛化证据。

部署候选仅使用种子 17 和三种基线。质量下限为 max(CF-blend, A-frozen-s17) 验证 NDCG 的 97%；通过者按冷目标 Recall@20、整体 NDCG、配置中的声明顺序选一个。若都无收益仍报告原路径，全部方法仍进入一次最终测试。

## 指标、资源与不确定性

主观察为冷目标入池率和整体 NDCG@10；并列整体、历史存在、无历史、冷目标、历史存在且冷、无历史且冷分组。记录候选覆盖、Recall@20、目标入池后的 Top20 转化率、实际候选大小。分母包括所有符合分组定义的正反馈请求，不因召回失败删除评估请求。

记录每批检索累计耗时、评分向量点积数、峰值显存与进程内存；训练、候选准备与排序耗时分开。GPU 批量时间不是线上 p95；不作线上性能结论。A/B 使用同一协同列表和同一内容均值列表，复用耗时单独标明。

对配置中的 5 组固定比较、5 个人群、NDCG@10 / Recall@20，使用三个固定种子的逐请求指标平均（非集成排序），按用户整体配对 bootstrap 10,000 次，种子 20260917，95% 百分位边际区间。全部 50 项区间披露；空组或少于两个用户明确不可计算。另报三个种子的均值与样本标准差。区间不含训练随机性、未校正多重比较，未处理跨用户时间和商品共同冲击。
