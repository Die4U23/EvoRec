# R02 / R03 训练与评价协议 v1

锁定日期：2026-09-15。适用范围：Video_Games 用户哈希样本的统计基线与自注意力序列模型。实时结果见 [持续实验报告](training-report.md) 和 [可刷新页面](training-report.html)。

## 数据与开发隔离

完整扫描官方 0-core rating-only 文件的 4,555,500 条交互，文件 SHA-256 为：

`30692f9806e33a7b5d8b599b73d7ca33dbfefb0abdfc1578052a101f2e64b3cd`

上游文件格式及全局时间边界来自 [Amazon Reviews 2023 官方说明](https://amazon-reviews-2023.github.io/data_processing/0core.html)。完整 gzip 校验已经通过；这不替代对上游去重策略或原始评论的复核。

选择规则为：对固定字符串 evorec-r02-v1 与用户 ID 计算 SHA-256，取前 8 字节的大端整数，模 20 为 0 时保留该用户的全部交互。R01 前缀出现过的 20,375 个开发用户全部排除。用户是否入选不依赖评分、历史长度或未来是否活跃。

最终得到 226,172 条交互、137,103 个用户。样本 SHA-256：

`790f07754b5e9f9b9a3be179085b61278388f20869c273da5e280704049b0c3c`

商品首次观察时间从完整类别提取，覆盖 137,249 件商品，单独保存校验值。模型学习仅使用所选用户的训练数据，商品可用时间代理来自完整类别；两种来源不能混同。

## 时间、历史与目标

训练截止 1628643414042，验证截止 1658002729837，均为 Unix 毫秒。训练严格小于前者，验证包含前者而不包含后者，测试从后者开始。代码对秒与毫秒混用和异常评分直接报错。

评分至少为 4 的评论作为兴趣正反馈。所有较早评论过的商品从候选中排除；兴趣历史只包含较早正反馈，最长 50 件。相同时间戳的事件共同读取此前状态，随后再一起进入历史。稳定的商品 ID 顺序只用于消除同时间戳的不确定性，不代表真实先后。

一件商品必须在完整类别中存在严格早于请求时刻的交互才可推荐。这仍是观察时间代理，不是真实上架时间，也没有声称静态商品资料在历史时刻可见。

主口径保留所有正反馈，包括目标尚不可用的事件；后者记为未命中。另报目标可用、已有历史、冷用户、模型冷且可用分组。模型冷表示当前模型的训练期没有该商品交互，而非全站没有交互。

## 拟合、调参与测试隔离

统计模型从训练正反馈计算。序列模型的 30,394 件商品词表仅由训练正反馈构造，产生 54,060 个非空历史的下一商品训练样例。未知商品不会通过测试标签加入词表。

训练采用完整训练词表交叉熵，不使用采样负例进行主评价。早停依据为验证集全部正反馈事件的 NDCG@10；最多 12 轮，连续 3 轮未改善停止。比较两种学习率 0.001 与 0.0003，其余网络配置固定为 64 维、2 层、2 个注意力头、dropout 0.2，batch size 256。

先用种子 17 选择网络配置，再使用相同配置训练种子 29 和 43。每个种子单独按验证集保存最佳轮次。测试查询在全部选定训练结束后才由程序显式解封；此后不根据测试分数修改本轮配置。

本轮同时比较固定的热门、365 天半衰期热门、ItemCF、两种协同与近期热门混合。混合参数在训练开始前写入程序，模型选择只依据验证集。展示各预声明方法的测试结果不意味着允许继续对同一测试集调参。

## 自注意力模型的实现边界

模型参考 [Self-Attentive Sequential Recommendation](https://arxiv.org/abs/1808.09781) 的因果自注意力序列建模思路。本项目使用 PyTorch Transformer 编码器、完整词表交叉熵、共享输入 / 输出商品嵌入，以及按训练频率初始化的可学习输出偏置。训练目标取每条非空前缀的下一商品。

这些选择与原始论文实现并不完全相同，因此名称标记为项目 SASRec-CE / SASRec-style 实现，不能宣称已经严格复现论文。后续要对照官方实现和一致协议，再决定将其列为正式强基线。

没有可映射历史的请求显式回退到训练热门列表。候选按当前时间和已交互集合过滤，最多 200 件。模型冷商品没有训练词表入口，因此内容检索仍是后续需要加入的独立路径。

## 可重复性与持续报告

记录代码快照、配置、数据与商品时刻校验值、每轮损失、验证指标、最佳检查点和随机种子。检查点加载时检查协议 ID 与商品词表，重载后重新核对验证指标。测试轨迹保留在本地 artifacts/，汇总与校验值进入文档。

训练使用本机已经可用的 PyTorch 2.9.0+cu126；实际完成过 GPU 前向与反向验证。研究虚拟环境复用系统包，不改变服务环境。依赖观察与复建说明见 [研究环境记录](../../research/environment-observed.json) 和 [训练依赖快照](../../research/requirements-training.lock.txt)。PyTorch 安装渠道见 [官方版本文档](https://pytorch.org/get-started/previous-versions/)。

每轮训练结束后自动生成 JSON、Markdown、HTML 和 PNG / SVG 图表。HTML 每 30 秒刷新。不同数据指纹的结果不放在同一比较柱状图中；R01 前缀报告继续单独保存。

训练损失、验证质量、冷物品表现与资源成本分别解释。GPU 批量评价只记录整批耗时，不能把它转换成在线请求 p95。多种子均值与波动不是统计显著性的证明；是否优于基线还需要配对比较与更多协议验证。
