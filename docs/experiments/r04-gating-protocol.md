# R04：固定模型下的冷商品保留与规则门控

登记：2026-09-15，查看本轮验证与测试结果之前。配置：[r04-gating.json](../../research/configs/r04-gating.json)。

## 问题与隔离

R03 的双塔融合改善了整体排序，但冷商品命中低于纯内容路径。本轮固定 R03 已训练的三个模型、最佳轮次、TF-IDF / SVD 编码器与统计训练数据，只改变候选排序策略，不重新训练或挑选模型权重。

新查询用户来自原哈希规则模 20 余数 2，并排除 R01 开发用户；R02 余数 0、R03 余数 1，因此用户不重合。用户的训练期交互仅用于形成请求历史，不用于重新拟合模型。商品与日历区间仍重合。

模型冷商品必须相对于 **R03 模型训练商品集合** 定义，不能相对于新查询样本重新定义。标题 / 类别仍采用静态快照可用假设；不证明严格历史内容回放或线上收益。

## 请求可见信息

门控只读取正反馈历史中可表示的商品数量，以及它们的内容一致性。一致性定义为：按 0.8 衰减的单位内容向量加权和的长度，除以权重总和。门控阈值预先固定为有效历史至少 2 件且一致性至少 0.6。

模型冷候选的判断只比较候选 ID 与冻结训练集合。策略接口不接收目标商品、目标冷启动标签或未来反馈。当前模型会执行两条候选路径；规则门控不等于省去其中一路计算，不能据此宣称预算路由加速。

## 五种策略

固定融合以 R03 的 0.5 内容权重和常数 60 进行倒数排名融合，输出最多 200 件商品。另比较固定保留 1 / 2 个冷商品位置，以及通过门控后保留 1 / 2 个位置。

保留策略从纯内容 Top-200 的合法冷商品中选取。若原 Top-20 已达到配额，则原样返回；否则保留已有的冷商品并补足，配额 1 放在第 20 位，配额 2 放在第 10 与 20 位。无足够冷候选时仅使用实际可得数量；稳定去重，候选总数不超过 200。不得伪造候选填满配额。

五种策略预先声明。以种子 17 的验证集选择：先要求整体 NDCG@10 不低于固定融合的 97%，再最大化模型冷且可用分组 Recall@20；同分时优先整体 NDCG 更高、保留位置更少、声明顺序更早的策略。固定融合始终参与比较，因此可以得出“不应采用新策略”的结果。

## 最终评估与证据

选定策略对三个冻结种子一致应用。报告固定融合与所选策略三种子均值 / 样本标准差；种子 17 展示全部预声明策略，检验是否需要门控。测试集在选型后开启，不根据测试结果调整门控阈值、配额或模型。

核对用户隔离、冻结文件哈希、严格时间历史、候选合法性、门控输入、实际触发数、原始结果与分组指标。记录质量 / 冷商品召回图、门控触发率和逐请求轨迹。主结果继续保留所有正反馈事件作为分母。
