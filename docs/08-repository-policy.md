# 仓库范围与版本约定

项目由 Die4U23 发起并主导。作者提出研究目标和总体方向、决定范围与优先级，使用编程助手辅助实现、测试及材料整理。项目归属与技术结论分别说明；所有指标保留实际运行证据，不改写训练日期或编造开发经历。

## 公开与本地材料

- 公开：项目源码、配置、接口与架构文档、测试、实验协议、汇总报告、结果图表和审计记录。
- 本地：博客正文与图片副本、实习指导、求职材料；通过明确的忽略路径排除。
- 本地且敏感：数据、用户级轨迹、模型、缓存和环境。分别放 datasets、artifacts、.venv / .venv-research；临时日志与测试目录放 tmp。
- 未识别的用户文件不自动纳入，也不自动删除。目前 LICENSE 保留待单独处理。

2026-09-17 使用停止跟踪方式移出 45 个博客或实习相关文件，逐文件核对本地内容未变。历史运行记录中的博客交付描述属于当时事实；历史 JSON 证据保持原样。R04 展示页仅将博客入口改为项目概览，未改变任何指标。旧交付检查继续强制验证实验本体，本地博客资源检查仅在资源存在时执行。

## 每阶段的提交边界

1. 协议先提交并推送，再构造样本、训练或查看验证结果。
2. 实现与必要测试通过后独立提交并推送。正式训练要求源码、配置、测试和检查脚本无未提交改动；保存代码版本和输入指纹。
3. 汇总结果、审计及图表单独提交。失败或无收益也记录；运行目录不可覆盖。
4. 只显式暂存本阶段路径。使用脚本检查 Git 暂存区中的路径、大小、常见凭据特征和文档本地链接，防止本地忽略文件掩盖发布缺失。
5. 推送后对照本地与远程 SHA。独立研究使用 codex/ 分支；先前 PR 未合并时注明依赖分支，不混淆各阶段差异。

历史提交绑定训练与审计的来源。目前采用追加清理提交，保留该对应关系。如未来确需改写历史，应同时处理所有依赖分支和 PR、保留旧新提交映射，并重建可复现来源；不能只改 Git 而让实验记录失去来源。

检查入口：scripts/check_repository_hygiene.py。报告默认写入忽略的 tmp 目录，确认后才将阶段证据复制到 docs/validation。首次 clone 不包含本地材料；实验复现不应依赖它们。
