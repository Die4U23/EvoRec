# 本地稳定版收尾计划（2026-10-10）

范围是本地单实例、批准的完整冻结 R06 包（137,249 商品）、NumPy、原 2 秒服务期限；新品仍使用独立内容基线。不是公网、多机或 PRD 20 QPS / p95 300 ms 的交付承诺。主目录及 8000 不操作，所有实库测试使用确切自有临时 schema 与随机 loopback 端口。

## 固定检查顺序

1. 在干净当前源上执行 24 笔双并发、未插桩、不重试的 TCP 基线；记录全部成功/失败及身份、正常清退，不因失败增加样本或换键重跑。
2. 按实际数据校验与取消清退不变的原则实现一个有界候选；先用实库反例验证，再在干净候选源执行同样 24 笔双并发。不把不同运行的差值当因果证明。
3. 候选门禁要求全部响应身份正确、无非法商品及清退完成。若有失败，保留记录并继续定位，不能宣称稳定。
4. 功能候选通过后，用独立 schema/进程做两轮各 120 笔双并发、未插桩、不重试的恢复与负载验收；要求两轮恢复检查与全部请求都通过。所有失败计入分母，不将脚本退出 0 或 CI 全绿当负载通过。
5. 完成服务/数值/页面/合约回归、浏览器主流程、备份恢复与 PR 精确 head CI；再决定依赖 PR 的合并和版本冻结。尚未执行的项目保持未完成。

## 修复约束

每次捕获必须核对实际数据库成员（含下架项）、顺序/内部 ID、有效商品的实际 UTF-8 文本与原始时间、资格集合；不信任数据库中可修改的摘要或客户端声明。请求使用单一目录读视图，保留完整已见和持久内容封印。不得延长超时、换用小模型或删掉失败/零跳过门禁。

现有间歇 orphan 回归失败没有足够原始状态定位；独立审计和有界重复测试只增加证据，不能倒推已经找到旧失败根因。作者亲自解释/修改代码不由代理代签。

## 目录候选下一轮的预登记口径

候选先从实际成员读取 N+1 条，数量不等于批准数量时跳过商品连接与文本哈希；不使用批准 ID 过滤器。功能对照覆盖成员、索引、文本、时间、NULL、下架/恢复和 SQL 期间并发修改。开发阶段旧聚合候选 349 项 XML 对应的字节随后保存在 `a65c1eb`，不是干净提交上重新执行的证据；N+1 开发测试另有 28 项通过，后续测量必须绑定新提交。

完整数据 SQL 诊断在独立 schema 上固定全部上架、3 项下架两种状态，每种按旧/新/新/旧各一次，分别记录 execute、fetch/decode 和候选资格验证耗时。执行计划另行采集 `EXPLAIN (ANALYZE, BUFFERS, TIMING OFF, FORMAT JSON)`，包含越界一项，保存扫描行数、循环、排序、临时块；计划观测耗时不混入请求压测。此诊断不是完整 HTTP A/B 对照，资格预期对象来自本轮经批准包发布的初始目录，不能替代独立等价测试。

随后干净候选执行 24 笔双并发、关闭插桩、不重试，保持每笔新建 HTTP 客户端、同一 session、不同请求键、原 2 秒期限、单排名 worker。客户端创建、HTTP 往返和总耗时分别报告；顺序总耗时不能直接证明服务端余量。

只有初筛全部通过，才执行预定旧 A/新 B/新 B/旧 A 四轮，每轮 24 笔及 2 笔顺序预热，独立 schema/服务进程、同一 sample 历史与 dense/k=10 请求序列，保留所有轮次。复用客户端、独立 session 各自作为之后的单变量诊断，不能只给候选使用。记录源码/模型/数据库版本及机器环境；不把四轮有限样本外推长期 SLA。

如初筛有失败，则本轮只补 8 笔双并发及 2 笔顺序的固定阶段诊断，保留成功和失败，不修改连接、恢复锁、worker 或期限。下一项实现由真实时间线决定：恢复、目录、排名等待/执行、结果写入、取消清退。execute 墙钟时间不等于锁等待；没有等待事件/阻塞者证据就不下锁或 GIL 结论。
