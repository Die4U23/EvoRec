# 本地稳定版收尾计划（2026-10-10）

范围是本地单实例、批准的完整冻结 R06 包（137,249 商品）、NumPy、原 2 秒服务期限；新品仍使用独立内容基线。不是公网、多机或 PRD 20 QPS / p95 300 ms 的交付承诺。主目录及 8000 不操作，所有实库测试使用确切自有临时 schema 与随机 loopback 端口。

## 固定检查顺序

1. 在干净当前源上执行 24 笔双并发、未插桩、不重试的 TCP 基线；记录全部成功/失败及身份、正常清退，不因失败增加样本或换键重跑。
2. 按实际数据校验与取消清退不变的原则实现一个有界候选；先用实库反例验证，再在干净候选源执行同样 24 笔双并发。不把不同运行的差值当因果证明。
3. 候选门禁要求全部响应身份正确、无非法商品及清退完成。若有失败，保留记录并继续定位，不能宣称稳定。
4. 功能候选通过后，用独立 schema/进程做两轮各 120 笔双并发、未插桩、不重试的恢复与负载验收；要求两轮恢复检查与全部请求都通过。所有失败计入分母，不将脚本退出 0 或 CI 全绿当负载通过。
5. 完成服务/数值/页面/合约回归、浏览器主流程、备份恢复与 PR 精确 head CI；再决定依赖 PR 的合并和版本冻结。尚未执行的项目保持未完成。

## 修复约束

每次捕获必须核对实际数据库成员（含下架项）、顺序/内部 ID、有效商品的实际 UTF-8 文本与原始时间、资格集合；不信任数据库中可修改的摘要或客户端声明。请求使用单一目录读视图，保留完整已见和持久内容封印。不得延长超时、换用小模型或删掉失败/零跳过门禁。

现有间歇 orphan 回归失败没有足够原始状态定位；独立审计和有界重复测试只增加证据，不能倒推已经找到旧失败根因。作者亲自解释/修改代码不由代理代签。
