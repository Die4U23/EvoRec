# 策略对比迟到响应隔离

日期：2026-10-23。基线：`9d7b027702c7eab0d315c641a5849496a0b05027`。

## 实际问题

推荐和反馈已有请求代数隔离，但策略对比的预览、保存和重查主要依赖会话 ID。重置保留同一 ID，因此旧保存响应可以重新写入已清除的对比编号和结果；切换等待期间的旧错误也可以覆盖进度提示。同一会话连续预览时，没有请求先后检查，先发后到的响应会覆盖新结果。反馈同步清除旧对比后，未结束的旧预览也可把旧历史快照重新显示出来。

## 修复

三类结果显示请求通过 `beginComparisonView` 捕获显示代数、会话切换代数及会话 ID/epoch。只有仍属于当前显示请求的成功或失败响应可以改变结果区及提示。接受会话同步、清除会话结果和开始新对比都会使旧显示请求失效；切换期间不再发起预览、保存或重查。

过期保存响应不清除原待确认编号，手动重试仍使用原请求和输入；当前请求失败继续显示错误。这里检查的是发起请求时的页面身份，不要求历史记录与当前 epoch 相同，因此重置后主动重查历史结果仍然有效。此改动不会取消已经发到服务器的保存操作。
