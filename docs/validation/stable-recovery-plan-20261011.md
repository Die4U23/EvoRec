## 非空、独立、可反证的门禁

现有恢复工具刻意把负载标为 measured_not_sla；不能仅用 exit 0 宣称零失败。本轮增加 opt-in 严格模式和独立离线证据检查器。每笔样本先保留索引、状态与 client 创建/HTTP/校验/close/总时间，即使 504、transport 或非法身份，也不能因 worker 抛错丢失分母。120 样本全部收齐后才判定负载：恰好 0..119、全部 200、合法模型/会话/请求键/epoch/history_version、有限分数且无重复/已见商品。请求键、令牌及正文只留本轮内存，不写公开/私有报告。

在 schema 删除前，使用独立只读数据库连接，逐笔检查唯一 completed、绑定身份/模型快照/捕获时刻、位置/分数/来源与 HTTP 返回一致，租约锁已释放、无 accepted 遗留；只输出数字/布尔门禁和失败索引，不保存私密请求内容。断连、同键与硬杀的原键同样独立核对持久终态；failed 原键无结果，completed 原键结果保持精确一致，失败清理不能覆盖 completed。硬杀前必须真正观察 accepted+owner，不能以无请求崩溃替代。

反例测试覆盖一个 504、一个 transport、错误键/epoch/version、错模型/重复/已见/非有限分数、假 completed/少行/位置错误/owner 锁未释放、缺样本/重复索引、汇总篡改、恢复标志缺失、缺正常清退/错误 hard-kill 生命周期，以及敏感内容不落盘。独立 checker 重算汇总，检查完整源码/模型/生命周期，不能只信 passed 字符串或预先声明的布尔值。

## 停止规则及结论边界

合法 HTTP 失败仍完成当前固定 120 笔并全部计数；负载零失败/身份/持久门禁失败时保留 observations、执行安全清退，停止本轮后续恢复及下一轮，不改代码后自动重跑本协议。启动、源/配置错误或无法安全清退立即停止，不冒充 120 已完成。每轮结束独立实查确切 owned schema、所有实际 PID/监听不存在，主工作区/.env/模型未变；等待检查进程结束后才做后续操作。新缺陷及验收操作异常发现时立即落盘本地事件，结果阶段更新台账。

两轮通过只支持“该冻结版本通过指定本地负载及恢复场景”，不是 20 QPS、300 ms、99% 或长期稳定性证明。浏览器/会话 reset 过期响应、备份恢复仍是独立后续门禁；production_acceptance=false、sla_proven=false；失败内部阶段若未插桩仍 unknown，根据实际阶段证据再登记下一项修改。
