## 发现与处理

catalog 原来只在 `asyncio.run(serve_catalog(...))` 正常返回后设置 `drained=True`。Uvicorn 处理 Ctrl+C、关闭监听后重新抛出信号，跳过赋值，即使 worker 已结束也写 false。现在由 worker 自身 finally 设置退出 Event，run 的清退 marker 读取真实状态；不吞掉工作线程异常、不用强杀代替 drain。

Windows 终端工具在 Ctrl+C 后报告的宿主退出状态为 1，四次均原样记录；不把这个宿主状态写成 Python 子进程 exit=0，也不单凭它认定清退失败。判断依据为线程完成标记和独立的 PID/监听/schema/令牌检查。本轮验证正常停止时空闲 worker/CPU 退出；正在执行工作时的取消隔离见针对性测试与此前生命周期验收，不能把本次手动退出扩大为所有强杀场景。

以下检查和操作问题均保留，不隐去失败分母：

- 首次回归缺少数据库环境变量，1 项 setup error；配置后旧实现 1 项断言失败，证实 marker 缺陷。
- 首轮组合测试在系统 pytest 临时目录遇到权限错误，101 项中 79 个 setup error、22 个通过；改用全新且限定于本轮的 `--basetemp` 后 101/101 通过，没有改系统目录权限。
- 浏览器在会话创建尚未完成时过早点击推荐，被页面提示先开始体验；待会话建立后继续。一次下架输入带了意外前缀，被服务拒绝；核对输入后下架正确商品。没有由此修改业务校验或隐藏失败。
- 初轮 R06 的临时账本 helper 错把两个不同新请求的全部分数要求完全一致；断言失败后，该轮已停止，原查询未落盘，因此该轮不声明完整独立账本通过。补充轮先保存账本，再按会话状态、合法身份、结果 ID/顺序、终态及租约检查；观测新请求最大分数差 `3.5762786865234375e-07`。两次新计算不是原键重放，完整响应一致只要求原键重放，相关原键保证仍由既有恢复验收证明。本轮未修改生产代码或原有重放断言。
