## 观测实现与功能门禁

只修改 opt-in 隔离进程诊断及其测试。记录原 `asyncio.Timeout` 期限回调的执行区间（不是计划期限、也不是首次收到取消），原 Recommend 工作流退出、原数据库/CPU `_drain` 的进入与完成、CPU 真实工作起止、执行租约关闭、ASGI 响应开始/最后 body 完成。复用既有单调时钟和 request-local ContextVar；标签固定，不保存参数、正文、令牌、SQL 或异常消息。原调用、返回对象、异常、取消次数与资源所有权保持不变。私有回调不可用必须失败，不能伪造已观测。

增加 504 轨迹完整性门禁：必须存在有限非负、有序的期限回调、工作流 TimeoutError、已完成清退和响应证据；若已进入 execution admission，则必须有成功的租约关闭；未进入该阶段的恢复超时不伪造租约。超时期间 result_write 可能已经提交，不能把 504 一律归为持久 failed；本轮不增加同键重放以改变固定请求批次，也不宣称终态恢复验证已完成。没有 504 时覆盖字段为 null，不用空集合 all 宣称失败门禁通过。诊断完整不等于零失败、性能验收或 SLA。

测试覆盖真实到期、重复取消、CPU 尚未退出时不提前完成、数据库线程清退、成功/异常返回身份、并发归属及补丁恢复。增加删除/错误/NaN/负数/时间倒置等负面观测门禁，缺任何必要失败证据就拒绝 CLI 的诊断完整出口。复用真实 PostgreSQL/合成包测试，保留零跳过门禁；主线程按质量、性能、复用三方面复核，不冒充独立审查（team-mode 当前接口无必需的 agent_type）。
