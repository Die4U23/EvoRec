# 后台对比轮询与恢复

日期：2026-10-25。基线：`4ed5133474600fbed6608dc8e4f31c088a314294`。

## 问题与修复

后台任务每秒发起一次状态查询，没有在途检查。慢查询期间，后续 tick 和手动查询会叠加请求；取消操作完成后，更早查询返回的 running 状态还可重新开启取消按钮和轮询。原检查主要依赖会话 ID 和任务 ID，不能隔离重置等待期间的响应或同一目标的过期请求错误。

任务完成后会先停止轮询，再读取保存的对比结果。如果结果读取暂时失败，原页面提示会继续重试，但实际上没有计时器继续查询。

本次将提交、状态读取和取消的响应处理集中到 `requestComparisonJob`，捕获请求代数、会话切换代数、会话 ID/epoch 及任务 ID。旧成功与错误均不能更新当前页面。在同一目标已有有效请求时，轮询和手动读取直接返回，重复取消也不会叠加 POST；取消允许替代此前状态查询。旧请求结束只能释放自己的在途标记，不能解锁较新的请求。

切换会话期间暂停任务操作和 tick，成功切换清理目标，失败则允许继续查询原任务。当前轮询失败保留原任务编号并重新安排查询，包括完成状态后的结果读取失败；正确取得终态及结果后停止。过期计时器回调不能停止新的计时器。网络请求已发送后不会被本地代数取消，服务端任务仍遵循原持久化与取消协议。

## 边界

本轮只修改前端任务状态请求与恢复，不改变后端租约、worker 并行度、取消协议、模型或期限；历史列表分页仍留待单独检查。验证使用确定性延迟注入和接口回归，没有另跑真实浏览器故障注入、R06 负载或生产 SLA 验收。同一目标的重复读取被抑制；切换目标后旧网络请求仍可能在途，不宣称全站请求被统一限流。
