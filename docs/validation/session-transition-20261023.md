## 问题与修复

原页面的开始、重置各自发起请求，连续点击可以同时提交多个创建或重置操作。后返回的旧响应可能覆盖先完成的新状态。此外，仅检查会话 ID 和 epoch 不够：切换请求还在等待时，两者仍是旧值，之前的推荐或反馈就可能继续修改页面。

现在统一由 `changeSession` 串行处理开始与重置。点击时立即增加本地请求代数，禁用身份选择、开始、重置和推荐入口；卡片反馈及撤销也拒绝新的提交。推荐、卡片详情、反馈响应和会话读取分别检查发起时的代数，旧操作不会在切换等待期更新当前页面。代数只用于前端隔离，不替代服务器会话 epoch。

失败路径通过 `finally` 解锁。原推荐编号与输入继续保留，迟到响应不清除它；反馈 POST 完成、但随后状态 GET 被切换作废时，也保留原事件编号。这样用户再次点击详情时重放同一事件，而不是把同一次未确认操作变成第二次历史记录。切换失败后，原卡片的新操作捕获新的本地代数，仍可使用。

范围为 `web/index.html`、页面测试和说明。API、数据库结构、算法、模型、候选资格、worker 数与期限未变。本地学习 PRD 未修改，也未加入 Git。

## 复核与边界

主线程复核了操作锁的释放、异步结果生效条件和重试编号保留，复用现有请求、错误显示与会话清理逻辑。代理接口不具备 team-mode 要求的角色参数，本轮没有独立子代理审查。

这轮隔离范围是推荐与卡片反馈，以及开始/重置的互斥；未统一改造策略对比等其他异步界面。网络失败不证明服务器未执行创建或重置，也未新增这两个接口的幂等协议。修改提供页面恢复与竞态保护，不代表生产 SLA、完整故障恢复协议或推荐效果提升。
