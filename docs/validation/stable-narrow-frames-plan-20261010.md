# 目录窄帧候选：本轮预登记

本轮只改变实际目录 SQL 的哈希输入与排序组织。上一轮候选有 9 次 504，不能作为稳定版；失败内部阶段仍未知。本轮不改 2 秒期限、单排名 worker、连接复用、恢复锁、GC、批准包、持久 canonical seal 和取消清退。

## 实现与功能门禁

保留实际 N+1 成员物化及数量门禁，将实际文本 SHA-256 和原始时间先组成 active frame，再物化只有 ID、索引、状态、NULL 标志和校验帧的行。聚合继续显式按内部索引排序；不依赖隐含顺序、不缓存实际可修改字段、不先筛批准 ID。所有内容仍取自单条 statement 的视图。

已有独立旧行谓词、持久 seal 对照、成员及内容反例、SQL 执行中并发修改全部保留。新增会抛异常的实库文本函数，证明 N+1 越界及全部下架确实不执行文本哈希，而不是仅返回零计数。测试采用自有 schema，任何失败与跳过都不计为通过。

## HTTP 条件门禁

功能及目录检查通过才执行候选初筛：独立 schema/服务进程，两笔顺序预热后固定 24 笔双并发、同一 session/不同新键、dense/k=10、每笔新建 HTTPX client、关闭服务插桩和 GC 观察、不重试、不扩样；全部失败计入分母。目录微测量不与 HTTP 并行。

若初筛通过，再按上一轮聚合 A / 窄帧 B / 窄帧 B / 上一轮聚合 A 固定四轮，各 24 笔加两笔顺序预热，独立 schema/进程、相同输入与期限。A 的生产源码必须保持精确 f21d7ae，禁止使用更早的全行捕获替代。所有轮次完整归档；客户端创建、HTTP 往返和总耗时分开，预启动 CPU 快照不是连续负载隔离。

若初筛有失败，仅补预定一批 8 笔双并发加两笔顺序的阶段诊断，保持相同参数和资源清退。A/B/B/A 有失败时也不进入两轮 120 笔最终验收；不能以成功轨迹解释失败，不能自动合并稳定版。最终恢复、浏览器、备份及版本冻结门禁仍独立保留。
