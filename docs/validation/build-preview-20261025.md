# 构建预览分页失败恢复

日期：2026-10-25。基线：`0643727e92b2770a28a54c253b9bd7a2e2d25dbb`。

## 现象与根因

翻页点击先修改全局 offset，再读取构建状态与预览。任一步读取失败都清除预览并禁用前后导航，用户无法直接重试翻页或返回；“查询状态与预览”也只能读取已提前移动的目标页。上次成功页的位置已丢失。

另一个实际缺陷：在旧构建的后续页点击“按最新商品库重新构建”，只有立即返回 ready 的分支重置 offset；常见的排队任务在 worker 完成后由轮询打开预览，沿用旧页码。旧构建有 45 件、停在第 41–45 件，新构建仅 3 件时，完成后的预览会显示空页而非这 3 件商品。

## 修复

导航将目标 offset 作为查询参数，完整预览成功才提交全局页码。失败继续清除旧商品资格、清空当前构建发布依据并禁用发布，仅恢复上次成功页的前后导航；点击原方向可重试同一目标，显式查询读取上次成功页。已有的请求代数与构建 ID 检查仍阻止迟到失败恢复失效导航。

新建构建时立即重置 offset，覆盖排队及即时完成两条路径。翻页处理函数同时检查按钮禁用状态，避免直接调用处理函数时改变页码或重复发请求；浏览器原生 disabled 已阻止普通用户点击，这项属于额外防御，不冒称真实浏览器双击缺陷。

- 3 个原先通过的检查保护切换构建与下架后的迟到失败隔离，以及正常首尾页往返边界。

## 边界
