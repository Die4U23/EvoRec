# 推荐反馈来源与撤销恢复

## 问题与修复

旧页面把撤销列表只保存在内存里，每次推荐成功还会清空它。隐藏状态已经保存在数据库，但刷新或重新推荐后用户失去了原入口。同时，反馈函数在调用时读取全局 `latest.request_id`：旧卡片的详情查询延迟返回后可能引用另一份推荐；反馈响应到达后还会直接更新全局会话，污染新会话或重置后的版本。

现在卡片捕获自身的推荐编号、会话编号与 epoch。反馈提交、状态刷新与显示更新分别核对当前身份；同 epoch 的迟到会话快照不得降低版本。重复在途反馈合并，反馈后查询失败时仍保留原事件编号，重试不会给已提交的详情浏览创建另一事件。

撤销记录随既有标签页状态保存。重新推荐不再清空它；刷新从服务器读取会话后，剔除其他会话、旧 epoch、已取消隐藏或结构非法的记录。撤销引用原推荐编号，只有原推荐仍显示时才补回原卡片，避免在新结果里插入旧商品。服务端仍校验商品来源和会话 epoch，前端记录不能绕过这些约束。

范围为 `web/index.html`、对应页面测试和使用说明。未修改 API、数据库结构、模型、训练参数、候选资格、worker 数或请求期限；此前本地学习 PRD 未改动或加入 Git。
