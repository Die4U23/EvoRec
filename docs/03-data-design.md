# 数据设计与一致性约定

早期 SQL 草案见 [db/schema.design.sql](../db/schema.design.sql)，仅用于演进参考，不直接执行。M1 正式迁移见 [db/migrations/0001_m1_core.sql](../db/migrations/0001_m1_core.sql)，已在本机 PostgreSQL 执行并验证。

2026-09-15 架构细化后，草案仍需补齐任务租约、发布操作幂等记录、bundle 商品成员快照、请求屏蔽快照与回退原因、反馈原处理结果，以及会话归属和收藏状态。具体事务边界以 [系统架构](02-architecture.md) 为准，现有十张表不代表这些协议已经实现。

## 1. 数据对象

| 对象 | 核心字段 | 约束 |
| --- | --- | --- |
| 商品 | 稳定 ID、标题、类别、内容、有效状态 | ID 唯一；内容以文本处理 |
| 会话 | 会话 ID、重置代数、历史版本、独立状态 | 示例原始历史不被覆盖 |
| 推荐请求 | 请求 ID、会话、代数、历史快照、bundle | 输入和实际执行路径可追溯 |
| 请求结果 | 请求 ID、商品 ID、名次 | 商品和名次在请求内唯一 |
| 反馈事件 | 事件 ID、请求商品对、类型、状态、时间 | 相同事件幂等，事件关联真实返回结果 |
| 导入批次 | 批次 ID、内容哈希、阶段、错误 | 同 ID 同内容重试复用；内容不同冲突 |
| 版本组合 | bundle ID、产物目录、哈希、状态 | 兼容性通过后才能发布 |
| 控制状态 | 活动 bundle、下架版本 | 切换与服务接收协调 |
| 后台任务 | 任务 ID、类型、状态、心跳、尝试次数 | 输出幂等，崩溃可恢复或明确失败 |
| 实验运行 | 运行 ID、配置、数据、代码与结果位置 | 未完成运行不展示为有效评估 |

## 2. ID、时间与版本

业务会话、请求、批次、事件和运行采用 UUID。商品采用外部稳定字符串 ID，当前契约允许字母、数字、点、下划线、冒号和短横线，长度 1-128；不自动改变大小写。

时间统一保存为带时区时间，内部规范化为 UTC。客户端观察时间与服务端接收时间分别记录；客户端时间不作为全局排序或并发仲裁依据。

会话重置使 epoch 增加，同时增加历史版本。旧 epoch 请求的反馈返回冲突，防止重置前的迟到事件重新污染会话。正常历史变化使用递增版本；每次有意义的变更只增加一次。

## 3. 反馈和幂等

收藏与屏蔽采用显式状态设置：favorite_set / hide_set 加 true 或 false。重试不会再次切换状态。详情浏览与曝光不携带状态值。

以 event_id 为幂等键，并保存规范化载荷哈希。首次处理时，在事务内检查请求属于当前会话、商品确实被返回、会话代数有效，再写事件与更新会话。同 ID 同内容返回原处理结果；同 ID 不同内容返回 409。

载荷哈希基于协议版本和经过规范化的客户端语义字段；字段名排序、UUID 和时间表示固定，不包含服务端接收时间。规范化算法和字段集在首次持久化实现时固定并写入测试。

曝光需要客户端提供可见比例和持续时间，正常曝光要求比例至少 0.5 且持续至少 1000 ms。用户先点击时，由服务端基于有效详情事件补记曝光。点击率按请求与商品对去重；事件 ID 去重与指标去重是两个层次。

## 4. 导入与版本

JSON 输入契约支持 1-1000 条商品；CSV 在校验后转换成同一结构。20 MB 文件上限在读取正文之前或流式读取期间执行，不能仅靠条数校验。字段错误和批内重复 ID 整批拒绝；与已有商品冲突由数据库及业务事务验证。

内容哈希在规范化字段与顺序约定下计算，批次重试不产生新发布。商品“已入库”“已发布”“具备内容候选资格”“获得实际曝光”分别记录或计算，不能合并为一个布尔标志。

模型产物置于不可变目录，数据库保存清单引用和状态。发布前验证文件完整性、商品映射、表示空间、语义码本与索引兼容性。数据库约束不能替代跨文件与内存的发布协议。

## 5. 离线与在线数据

离线数据使用 Parquet 快照和 DuckDB 查询；训练读取明确的时间切分。在线会话反馈保存在 PostgreSQL，不自动改写离线数据。原始数据目录和模型产物不进入 Git。

当前 Pydantic 契约只证明输入结构符合要求，不证明商品存在、用户有权限、事件来源真实、事务已经完成或模型兼容。这些检查分别在业务和产物加载层实现。
