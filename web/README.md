# 本地 Web 演示与前端规划

`web/index.html` 是可运行的零构建本地页面，由服务的 `/app` 提供；不要用 `file://` 直接打开。它覆盖会话、推荐、详情反馈、单件及 CSV/JSON 文件导入、内容处理预览、确认发布、下架与受控 bundle 恢复。文件上传先持久排队，保留批次 ID 供同文件重试，并展示 worker 校验后的逐行错误；页面重开后可输入批次 ID 恢复校验、导入和最近构建状态。“已导入”不等于“已发布”。文件校验与内容构建都需另启 `python -m scripts.catalog_worker`；worker 未运行时页面保持排队状态。进度与错误由数据库记录；同一构建失败后可重试。确认发布前可分页预览商品资格；活动版本变化时需重新构建。管理员令牌只存在当前页面内存中；页面不直接访问 PostgreSQL 或模型文件。它不是公开部署界面，也不展示离线研究指标为线上效果。

商品目录每页显示 20 件，支持上一页和下一页；这只影响目录浏览，不会自动把新导入商品加入活动推荐版本。

React、TypeScript、Vite、Ant Design、ECharts 仍是后续更完整前端的技术选项；当前先用原生 HTML/JS 验证 API 流程，避免把尚未实现的页面规划宣称为交付。

| 页面 | 核心状态 | 依赖 |
| --- | --- | --- |
| 推荐首页与详情 | 新用户、示例用户、加载、空列表、失败、反馈、重置 | M11-M14 |
| 商品工作台 | 待校验、处理中、待发布、已发布、失败、下架 | M21-M24 |
| 策略对比 | 输入固定、任务运行、完成、失败、差异查看 | M31、M41 |
| 效果看板 | 无结果、筛选、分组、样本数、版本追溯 | M41-M42 |

实现时从 API 的 OpenAPI/JSON Schema 建立类型约定。开发模拟数据须显式标为模拟，不能进入正式研究结果。推荐列表实际由服务生成，前端不伪造分数或点击率。

# 策略对比

开始会话后可点“对比当前会话”，以同一会话版本和活动商品库预览热门、受控稠密与自适应路径的结果。页面显示实际执行策略和回退原因；该预览不保存为评估任务，也不代表真实 R06 模型已上线。

配置 PostgreSQL 并应用 `0006_strategy_comparisons.sql` 后，“运行并保存对比”会保存完整快照与结果；响应丢失时重试沿用原编号和输入。“重查记录”读取已保存的历史结果，服务重启后仍可用。浏览器 `sessionStorage` 仅在当前标签页保存会话访问令牌、对比/任务编号和未确认的请求，刷新后恢复；关闭标签页后需自行保留原会话凭据才能查询，管理员令牌不会保存。历史结果不随商品下架或会话重置更新。

“查看已保存对比”按当前会话列出历史摘要，每页 10 条，可查看更近/更早记录并打开原始结果；`0007_comparison_history_index.sql` 为该查询添加索引。列表不会展示其他会话的记录。

应用 `0008_comparison_jobs.sql` 并在独立终端载入相同的 `EVOREC_DATABASE_URL`、`EVOREC_BUNDLE_ROOT`，运行 `.venv\Scripts\python.exe -m scripts.comparison_worker`（Linux 为 `.venv/bin/python`）。页面“提交后台对比”先冻结当前输入并保存任务，随后每秒查询状态；完成后自动取回完整结果。“取消任务”将运行中的任务显示为取消中，等待当前排序退出后确认，不假装 CPU/GPU 已被强制终止。“查询任务”支持输入原编号重开；失败或取消后需点“新建后台任务”才能发起新计算，新建不会自动取消旧任务。浏览器响应丢失后重试保留原任务输入与编号，worker 崩溃后按租约和尝试代数恢复。`.env` 不会被 worker 自动读取，必须先载入该终端环境；只启动 API 时任务会停在排队状态。

当前仅单次、同会话的受控 CPU 策略对比，批量样本评估、真实 R06 生成式/混合模型、正式性能指标和效果看板仍未实现。
